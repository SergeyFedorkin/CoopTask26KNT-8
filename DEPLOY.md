# 🚀 Деплой на VPS

Схема: бот работает на **российском** сервере, потому что RUZ отвечает только российским IP. В Telegram он ходит через SSH-туннель на **зарубежный** сервер, потому что с российских серверов api.telegram.org сейчас часто недоступен.

```
Telegram ◀── HTTPS ── Зарубежный VPS ◀── SSH-туннель ── Российский VPS (бот + SQLite) ── HTTPS ──▶ RUZ
                                                               ▲
                                              GitHub Actions ──┘  (пуш в main → автодеплой)
```

Время: примерно 30–40 минут.

## 0. Что купить

Два самых дешёвых VPS с **Ubuntu 24.04**, например VDSina за 150 ₽/мес каждый:
- **Москва** — это российский сервер, на нём живёт бот;
- **Амстердам** — это релей для Telegram.

Запиши себе IP и root-пароль от каждого.

## 1. Код в репозитории

Все 8 частей должны быть смерджены в `main`. Репозиторий лучше сделать **публичным**: тогда серверу не нужен ключ доступа к нему. Если репозиторий приватный, смотри шаг 3.

Проверь, что `.env` в репозиторий **не попал**: он есть в `.gitignore`.

## 2. Скопируй скрипты на серверы

С ноутбука (в Windows 10/11 `scp` и `ssh` уже есть в PowerShell):

```bash
scp deploy/setup_server.sh root@<IP_МОСКВА>:
scp deploy/setup_relay.sh  root@<IP_АМСТЕРДАМ>:
```

## 3. Запусти настройку российского сервера

```bash
ssh root@<IP_МОСКВА>
bash setup_server.sh https://github.com/<владелец>/<репо>.git <IP_АМСТЕРДАМ>
```

- Если репозиторий **приватный**, передай SSH-ссылку `git@github.com:<владелец>/<репо>.git`. Скрипт покажет ключ и будет ждать. Ключ добавляет **владелец репозитория**: Settings → Deploy keys → Add deploy key, без галочки write.
- Скрипт спросит **токен прод-бота**. Создай для прода отдельного бота в @BotFather, не тот, на котором тестируешь.
- Потом скрипт напечатает команду `bash setup_relay.sh '...ключ...'` и будет ждать.

## 4. Настрой зарубежный сервер (во втором окне терминала)

```bash
ssh root@<IP_АМСТЕРДАМ>
bash setup_relay.sh 'ssh-ed25519 AAAA... tunnel to relay'   # команда целиком из шага 3
```

Вернись в первое окно и нажми Enter. Скрипт поднимет туннель и бота и проверит, что Telegram и RUZ доступны.

## 5. Включи автодеплой

В конце скрипт напечатает `VPS_HOST` и приватный ключ `VPS_SSH_KEY`. Секреты может добавить только **владелец репозитория**. Отправь их ему в личку: ключ секретный, в общий чат его не кидай. Владелец добавляет их так: репозиторий → **Settings → Secrets and variables → Actions → New repository secret**, потом запускает **Actions → Deploy → Run workflow**, чтобы проверить.

После этого каждый пуш или мердж PR в `main` проверяется и сам выкатывается на сервер (вкладка **Actions**).

## Проверка и полезные команды (на российском сервере)

```bash
systemctl status diary-bot tg-tunnel            # оба должны быть active (running)
journalctl -u diary-bot -f                      # логи бота в реальном времени
journalctl -u tg-tunnel -n 30                   # логи туннеля
curl --socks5-hostname 127.0.0.1:1080 -sI https://api.telegram.org | head -1   # Telegram через туннель
curl -s "https://ruz.hse.ru/api/search?term=БПИ&type=group" | head -c 200       # RUZ напрямую
sudo -u diary bash /opt/diary_bot/deploy/update.sh                              # выкатить вручную
```

## Если что-то сломалось

| Симптом | Что делать |
|---|---|
| Бот не отвечает, в логах `TelegramNetworkError` | Туннель лёг: `systemctl restart tg-tunnel`, смотри `journalctl -u tg-tunnel`. Проверь, что зарубежный сервер жив. |
| `TelegramConflictError` | Этот же токен запущен где-то ещё, например у тебя на ноутбуке. Останови там. |
| «RUZ недоступен» | Проверь `curl` из списка выше. Если RUZ лежит, бот покажет кэш и ручные пары. |
| Actions падает на шаге выкатки | Проверь секреты `VPS_HOST` / `VPS_SSH_KEY`: ключ нужно вставлять целиком, с BEGIN/END. |
| После мерджа бот упал | `journalctl -u diary-bot -n 50`, исправить и запушить, либо `git revert` последнего коммита. |

База `diary.db` лежит в `/opt/diary_bot/` и при деплое не трогается. Бэкап: `cp /opt/diary_bot/diary.db ~/diary-$(date +%F).db`.
